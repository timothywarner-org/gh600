# Lesson 6: Perform Evaluation, Error Analysis, and Tuning

**Exam GH-600 domain:** Perform evaluation, error analysis, and tuning (15-20%)

## Learning objectives

Each objective is word for word from the course outline. Under it are the study guide skills it serves, with the IDs from the [exam objective map](../../docs/exam-objectives.md).

- 6.1 Define expected outcomes and operational constraints per agent task
  - Skill 4.1.1: Specify expected outcomes and operational constraints for agent tasks
- 6.2 Align qualitative and quantitative evaluation signals with development intent
  - Skill 4.1.2: Identify qualitative and quantitative evaluation signals to evaluate agents
  - Skill 4.1.3: Align evaluation criteria with development intent
- 6.3 Generate evaluation signals via CodeQL, dependency review, and secret scanning
  - Skill 4.1.4: Generate evaluation signals by using automated scanning tools
- 6.4 Analyze failures from logs, plans, traces, outputs, and workflow artifacts
  - Skill 4.2.1: Identify failures by using logs, plans, traces, outputs, and workflow artifacts
- 6.5 Classify root causes: reasoning errors, tool misuse, context or environment issues
  - Skill 4.2.2: Classify root causes, including reasoning errors, tool misuse, and context or environment issues
- 6.6 Tune agents by revising instructions, workflows, and constraints, refining memory usage, and rescoping tools
  - Skill 4.3.1: Revise instructions, workflows, or constraints
  - Skill 4.3.2: Refine memory usage
  - Skill 4.3.3: Refine tool usage and tool access

## Study guide skill groups

- Define success criteria and evaluation signals for agent tasks
- Analyze agent failures and identify root causes
- Tune agent behavior based on evaluation results

## Hands-on practice

Lab files for this lesson arrive when the lesson publishes. Its [`demos/`](demos/) page will list them in run order, and the files will live in [`lab/`](../../lab/). Do the [one-time lab setup](../../lab/README.md) now, so you're ready when they land.

Copilot agents rarely produce the same wording twice, so your results will read differently from the video. Look for the same outcome: the plan, the branch, the pull request, the blocked action, or the log entry.

## Before you start

- The accounts and tools in the [one-time lab setup](../../lab/README.md).
- Code scanning, dependency review, and secret scanning are free in public repositories. Private repositories need paid GitHub security products for them (GitHub Docs, checked November 14, 2026).
